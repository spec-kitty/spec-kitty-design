# Research: CLI Auth Pattern Stories

## Decision summary

The four canonical Family 5 CLI-auth states (code entry, authorization decision, terminal success/denial, terminal error) can be proven as one Storybook-only pattern module — `packages/elements/src/patterns/cli-auth.stories.ts` plus an immutable `cli-auth.fixture.ts` — composed entirely from public `@spec-kitty/tokens`, `@spec-kitty/styles`, `@spec-kitty/elements` surfaces and native semantic HTML. The mission adds no package, token, custom element, framework wrapper, state machine, or application service.

Three of the composed surfaces are not yet on `train/elements-first` at mission start: `#320` (`sk-button` danger-secondary), `#321` (`.sk-input`/`sk-form-input` contrast + target-size contract), and `#303` (`sk-boundary-page` public frame). None of their branches exist on `origin` as of this research pass (verified by `git ls-remote`, empty result for all three `mission/*` branch names). This mission may specify, plan, select fixtures, and scaffold red-first stories/tests now; it must not assert Story 2's Deny composition or Stories 3/4's terminal-frame composition as complete before the corresponding dependency lands and the lane rebases onto the train commit that carries it.

The existing `scripts/check-pattern-composition.mjs` gate (added by mission `composition-fixture-public-surfaces-01M1Y34S`, closing #259/epic #183) already scans `packages/elements/src/patterns/**/*.{ts,tsx,js,mjs,cjs,css}` for shadow-root reach-through and duplicated component CSS. Placing the CLI-auth fixture inside that existing directory means the gate covers it automatically — no new gate, no modification to the existing one.

This is one cohesive work package and one PR. Splitting fixtures from stories, or splitting the non-dependent scaffolding from the dependent finalization, across separate PRs would violate the repository's one-fixture-truth-source convention this programme has established four times already (mission-reading, repository-dossier, work-explorer, work-package-view) and would leave an unmergeable partial PR whenever a dependency has not yet landed.

## Binding interpretation of the four required stories

- **Code entry** composes the *current* `.sk-input`/`sk-form-input` contract unchanged. It does not wait for `#321` to exist as a class — the class is already public. What is genuinely blocked is verifying the contrast/target-size acceptance clauses (FR-011/FR-012 in spec.md), which can only pass once `#321`'s fix lands; the story itself is not blocked.
- **Review and decide** composes `sk-card` (or an equivalent card surface already public), `.sk-facts`, `sk-pill-tag` (neutral/variant axis, not status, for scope labels), and two buttons in one native `<form>`. Approve is unblocked (existing `sk-button` primary). Deny is genuinely blocked on `#320` — there is no existing public surface that expresses "secondary shape, danger meaning" without either forking CSS (forbidden by the issue) or reusing `--sk-status-danger` directly on `.sk-button--secondary` (also forbidden — that is exactly the local patch #320's own contract exists to prevent, and it would leave a second, uncoordinated fix to the same weak border token #155 already names).
- **Terminal success/denial** and **terminal error** both compose `sk-boundary-page`, which does not exist. Both stories are genuinely blocked in full; the mission scaffolds their fixtures, their story shells (red, failing to find the frame), and their test assertions now, and finalizes composition only once `#303` lands — or reports it as a missed dependency per the issue's explicit instruction, never substituting a local frame.
- "No fabricated action" for the terminal stories means: a terminal-outcome fixture renders zero actions unless it explicitly supplies one (label + href); the pattern itself never synthesizes a "try again," "go back," or "contact support" control.

## Architecture and file placement

- One fixture module, `packages/elements/src/patterns/cli-auth.fixture.ts`, exporting deep-frozen, immutable fixtures for all four states (code-entry default/invalid, authorization decision, terminal success/denial, terminal error with/without a supplied action) — following the `repository-dossier.fixture.ts` precedent rather than inlining fixtures in the stories module.
- One story module, `packages/elements/src/patterns/cli-auth.stories.ts`, importing the fixture module and composing markup from public element/style imports only. Pattern-owned layout classes use the `sk-cli-auth-pattern__*` BEM block and public tokens exclusively; no theme selector is written locally (ADR-9 §3; ADR ruling on `.sk-light`/`:root[data-theme]` inertness across a shadow boundary).
- Both files land inside `packages/elements/src/patterns/`, which `scripts/check-pattern-composition.mjs` already scans — confirmed by reading the gate's `SCAN` constant (`packages/elements/src/patterns/**/*.{ts,tsx,js,mjs,cjs,css}`). No gate code changes are needed or planned.
- A focused Storybook Playwright spec, `apps/storybook/src/tests/sk-cli-auth-pattern.spec.ts`, follows the `sk-repository-dossier-pattern.spec.ts` precedent: story-existence, non-empty-root, forbidden-tag/private-reach, keyboard-order, label/description-association, live-region, target-size, and fixture-consistency assertions.
- `expected-stories.json` gains one row per exported story ID; `apps/storybook/src/tests/visual.spec.ts` gains one case per required visual state (dark × 4 stories, LightMode, 390px, forced-colors, 200% zoom — baselines harvested from the CI `visual-regression-diffs` artifact, never shot locally).
- `docs/design-system/using-components.md` gains one short section naming the pattern and the exact consumer-owned behaviors: route, permission, session, validation, submission, confirmation, copy, localization, and terminal-state selection.
- The component-scoped no-literal assertion (FR-018) is a grep-style Node test asserting zero occurrences of each fixture's exact copy strings inside the source of `sk-button`, `.sk-input`/`sk-form-input`'s markup module, `sk-card`, `sk-pill-tag`, and (once landed) `sk-boundary-page` — the same DoD shape `#320`'s own issue names ("grep-style assertion consistent with #286's DoD pattern"), scoped here to the elements this mission actually composes rather than to the full element catalogue #286 covers.

## Alternatives rejected

| Alternative | Rejected because |
|---|---|
| Style a local `.sk-button--danger` class on the story markup ahead of `#320` | Forks CSS the issue explicitly forbids ("do not copy its pending CSS into the story to manufacture completion") and creates a second uncoordinated patch to the `#155` weak-border token `#320` exists to fix once. |
| Restyle `.sk-button--secondary` inline with `--sk-status-danger` as a stand-in | Same fork, one layer thinner; still not `#320`'s public contract and still invisible to the composition gate as "danger-secondary." |
| Build a local `sk-terminal-frame`/`sk-boundary-stage` composition ahead of `#303` | The issue's explicit non-goal and epic `#319`'s explicit exclusion: "A second `sk-boundary-page` or local boundary-frame fork... #303 owns the reusable frame." |
| Publish `auth-card`, `scope-chip`, or `form-action-row` | Named non-goals in both `#329` and `#319`; each is a one-story composition from existing elements and native semantics. |
| Replicate all twelve Family 5 screens (A1–A12) | The issue caps scope at four representative stories; exhaustive parity is an explicit post-2026-09-15 follow-up, not this mission's critical path. |
| Add a second composition/inventory gate scoped to CLI-auth specifically | `check-pattern-composition.mjs` already scans the whole `packages/elements/src/patterns/` directory; a second gate would duplicate R1–R4 for no new coverage. |
| Wait for `#320`/`#321`/`#303` to land before starting any mission work | Contradicts the epic's explicit Wave-2 parallelization instruction and would waste the window before the 2026-09-15 deadline that specification, fixture selection, and non-dependent scaffolding can use productively. |

## Risks and mitigations

- **`#303` misses the 2026-09-15 deadline entirely.** Mitigate by keeping Stories 3 and 4's non-dependent parts (fixtures, story shells, tests, documentation draft) complete and reviewable independently, and by making the mission's finalization step name the missing dependency explicitly in its status/PR body rather than silently shipping a workaround.
- **`#320`/`#321` land with a different final API shape than assumed here** (e.g., a `tone="danger"` attribute vs. a `--danger-secondary` modifier class). Mitigate by keeping the plan's dependent step generic ("consume whichever public API #320 ships") rather than hard-coding an assumed class name into the spec's acceptance criteria.
- **Visual baselines captured before the final dependency rebase describe pre-dependency code.** Mitigate by generating baselines only after the lane rebases onto the train commit(s) carrying the landed dependencies, per the repository's CI-authoritative baseline rule.
- **The composition gate's `MIN_COMPOSED_TAGS` (3) or `MIN_OWNED_CLASSES` (20) floors could be defeated by an unusually small fixture.** Mitigate by confirming during planning that the four stories together compose at least `sk-button`, `sk-form-input`/`.sk-input`, `sk-card`, `sk-pill-tag`, `.sk-facts`, and (once landed) `sk-boundary-page` — six distinct tags, comfortably above the floor.
- **A partial mission (only Stories 1 and 2 finalized) could be mistaken for done.** Mitigate by making the work package's Definition of Done explicit that all four stories, not a subset, are required before the mission's own acceptance gate passes — with the dependency-honest report as the one documented alternative outcome for Stories 3/4 if `#303` truly misses the date.

## Open questions

- Whether `#320` ships a new `tone="danger"` value on `sk-button` or a dedicated modifier composing secondary shape with danger coloring is left to `#320`'s own mission (explicitly "an implementation decision within this mission, not prescribed here" in its issue body). This mission's plan does not assume a class name; it names the *public contract point* (a danger-secondary combination reusing `--sk-status-danger`) and defers the exact selector to whatever `#320` lands.
- Whether `#303` exposes its title/body/footnote through slots, attributes, or both is similarly left open pending that mission's own implementation; this mission's plan composes the frame's documented public seam once landed rather than assuming a shape.
