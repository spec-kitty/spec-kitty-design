# Implementation Plan: sk-nav-pill Behaviour Element

**Branch**: `mission/sk-nav-pill-behaviour-element` | **Date**: 2026-09-03 | **Spec**: [spec.md](./spec.md)
**Issue**: #73 · part of epic #66 · **Squad tier**: C — pre-merge only

## Summary

Move `skToggleDrawer`'s twelve lines inside a `sk-nav-pill` custom element, replace the global
`id="sk-nav-drawer"` contract with `open()`/`close()`/`toggle()` plus a documented cancellable
event, own `aria-expanded`, Escape and focus return, and delete the helper with no shim. Then
prove each of those with a behaviour test whose deletion is measurably red — which requires one
enabling change to `behaviours.json` and one to the CSS pipeline.

This is the first **behavioural** component on the base layer. #72 proved a presentational one.

## Implementation Concern Map

### IC-01 — The element, and where the panel lives

- **Purpose**: `sk-nav-pill` on the base layer, owning the control and the panel in one root.
- **Relevant requirements**: FR-001, FR-002, FR-004, FR-006
- **Surfaces**: `packages/elements/src/nav-pill/sk-nav-pill.ts`, `packages/elements/src/index.ts`
- **Approach**: shadow root holds `<nav>`, a single items container wrapping one `<slot>`, and
  the hamburger `<button>`. `aria-controls` names the items container — same root, so it
  resolves under ADR-9's rule. One slot, presented two ways by CSS, is what makes FR-006
  possible: two slots cannot hold the same nodes, so a two-container arrangement would force
  the consumer to author items twice, which is the duplication being removed.
- **Risks**: the demo positions its drawer *outside* the nav, below the header, full width. A
  shadow-owned panel is positioned relative to the host. The demo's header CSS
  (`.dash-nav-drawer-wrap`, `.dash-header .sk-nav-pill`) must be re-checked at the breakpoint,
  not assumed — this is the most likely place for a visual regression that no assertion catches.
  Published prose stays short: a `/** */` above an export goes verbatim into the manifest.

### IC-02 — The event and method contract

- **Purpose**: a public API that is observable, idempotent and cancellable.
- **Relevant requirements**: FR-002, FR-003 · **Behaviours**: SC-006, SC-007, SC-008, SC-009
- **Surfaces**: the element; `fixtures/elements-behaviour/src/sk-nav-pill.test.ts`
- **Approach**: `open` reflected property/attribute; the state-change event fires only on a real
  change; `cancelable` on the *opening* transition so `preventDefault()` has something to
  prevent, and the assertion checks the element did **not** open rather than that the listener ran.
- **Risks**: the `preventDefault` test is the fakeable one — asserting `evt.defaultPrevented`
  proves the listener called the method, not that the element honoured it. Assert the state.
  Reflection plus a change event is the classic infinite-loop shape; the property setter must
  not re-enter through the attribute callback, and "fires exactly once" (SC-006) is the test
  that catches it.

### IC-03 — Keyboard, focus and the invoker

- **Purpose**: Escape closes and focus returns to whatever opened it.
- **Relevant requirements**: FR-004, FR-005 · **Behaviours**: SC-012
- **Surfaces**: the element; the behaviour test
- **Approach**: record the invoker at open time (`document.activeElement` at the moment `open()`
  is called, or the event target when opened from the internal hamburger). Do not assume the
  internal hamburger: `open()` is public and a consumer's control is a legitimate invoker —
  that is the whole point of replacing the global helper.
- **Risks**: `document.activeElement` inside a shadow root reports the **host**, not the inner
  button; the composed path is what identifies the real invoker. Focus return when the invoker
  has since been removed from the DOM must not throw (spec edge case). Escape on a *closed*
  panel must not steal focus — the easiest bug to ship and the easiest to miss.

### IC-04 — Deleting the helper, with nothing left behind

- **Purpose**: `skToggleDrawer` and its id contract gone from the repository.
- **Relevant requirements**: FR-007, FR-008, FR-009 · **Success**: SC-102, SC-109
- **Surfaces**: `sk-nav-pill.js`, `sk-nav-pill.d.ts`, both `index.ts` files, `packages/styles/README.md`,
  `sk-nav-pill.stories.ts`, `apps/demo/dashboard-demo.html`
- **Approach**: delete, then grep. SC-102's grep is the assertion; the frozen `kitty-specs/**`
  and the historical ADR/programme prose are the only permitted survivors.
- **Risks**: `packages/styles/README.md` documents the id contract in **three** places
  (`:58`, `:83-85`, `:100-106`) — a partial edit leaves a README teaching a deleted API. The demo
  must be checked on **both** path modes (hard rule 7); passing on `file://` proves nothing about
  the `sed`-rewritten deploy path.

### IC-05 — Two stylesheets for one component

- **Purpose**: the element adopts both nav-pill sheets without either being copied.
- **Relevant requirements**: FR-011, NFR-001, NFR-002 · **Success**: SC-107
- **Surfaces**: `scripts/build-elements-css.mjs`, `packages/styles/src/nav-pill/sk-nav-pill-drawer.css`
- **Approach**: the generator globs `sk-*.css` in the component's styles directory, sorted, and
  concatenates with per-file provenance. For a single-sheet component the output must be
  **byte-identical** to today's — `sk-card.css.js` under `git diff --exit-code` is the check, and
  it is a real risk because the header currently hardcodes one `Source of record:` line.
  The reflow rules are **added** to the drawer sheet, not substituted: static consumers still use
  the two-container arrangement until #77–#79 migrate them, and breaking them here would be
  collateral this mission has no mandate for.
- **Risks**: the orphan sweep is keyed on expected paths derived from the component list; it must
  keep working when one component maps to several sources. A missing sheet must stay a hard exit,
  not an empty concatenation — an empty stylesheet adopted silently is the certifying-absence
  shape in the CSS pipeline.

### IC-06 — Tests that cannot be deleted for free

- **Purpose**: every new behaviour test is load-bearing, and the floor knows it exists.
- **Relevant requirements**: FR-010, FR-012, NFR-004 · **Success**: SC-103, SC-104, SC-105, SC-106, SC-110
- **Surfaces**: `behaviours.json`, `scripts/floor-reporter.mjs`, `mutations.json`, `scripts/suite-selftest.mjs`
- **Approach**: `behaviours.json` entries gain a `subjects` list. The floor reporter checks
  coverage per **(id, subject)** rather than per id. Today it checks per id, and the synthetic
  fixture already covers every id this mission asserts — so deleting all of `sk-nav-pill`'s tests
  would leave the gate green. SC-106 proves the deletion goes red; it is not argued from FR-010.
- **Risks**: this is the highest-value and most fakeable piece of the mission. A `subjects` field
  that the reporter reads but does not enforce is worse than none, because the next reader
  believes it — the exact failure ADR-9's own consequences section names about depConstraints.
  The reporter's own change needs a red-first proof, not just the tests it guards.

### IC-07 — The a11y gate must see the open state

- **Purpose**: the keyboard path is axe-clean, not just the closed default.
- **Relevant requirements**: NFR-003 · **Success**: SC-108
- **Surfaces**: `packages/elements/src/nav-pill/sk-nav-pill.stories.ts`
- **Approach**: a story that renders with the panel **open**. The gate walks stories; a component
  whose only story is the closed state has had one of its two states tested.
- **Risks**: the axe gate's render predicate is flat-tree and slot-aware (#70) — a story that
  paints nothing until interaction reads as an unrendered story, not a passing one. The open
  story must render open on load, not open itself in a play function.
