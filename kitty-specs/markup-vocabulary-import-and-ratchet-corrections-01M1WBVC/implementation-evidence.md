## #216 — the generator, and the conversion that proves it

### What changed

`scripts/build-element-markup.mjs` evaluated each `*.markup.ts` from a `data:` URL. A `data:` URL
has no hierarchical base, so **no** import resolved there and the generator said so in a named
error. Per the operator ruling of 2026-09-06 it now imports each module from
`pathToFileURL(src).href` — the module's own path — with two synchronous `module.registerHooks`
hooks:

- `resolve` retargets a relative `.js` specifier that has no file behind it onto its `.ts` sibling.
  This is not optional: every relative import in this repository is written `.js` over a `.ts`
  source, and Node reports `ERR_MODULE_NOT_FOUND` for exactly that, measured before the change.
- `load` runs the already-pinned `esbuild.transformSync` over any `file:` URL ending `.ts`.

esbuild stays the transformer deliberately. Node 22.18+ strips types natively and would work, but
it is erasable-syntax-only and gated on the runner's Node **minor** (`node-version: '22'` resolves
to whatever 22.x is current). The change is *where* a module is evaluated, not *what* understands
the language.

`STATUS_TONES` moved to `packages/elements/src/status-indicator/status-tones.ts`, a leaf with no
imports, re-exported unchanged from `sk-status-indicator.ts`. It had to move: the element imports
`lit` and, through `define.js`, patches `customElements.define` at module scope, so the generator
cannot evaluate anything that reaches it.

`sk-card.markup.ts` now imports `STATUS_TONES` and derives `CARD_STATUSES`. `CardStatus` is aliased
to `StatusIndicatorTone` rather than left as `keyof typeof CARD_STATUSES`, because
`Object.fromEntries` widens keys to `string` and `isCardStatus` would have stopped narrowing.

### The parity assertion is KEPT, and re-aimed — the first revision of this was wrong

This mission first **deleted** the order-sensitive
`expect(Object.keys(CARD_STATUSES)).toEqual([...STATUS_TONES])`, reasoning that a derivation cannot
disagree with the array it is derived from. A pre-merge reviewer falsified that in one edit, and the
reasoning was wrong in a specific and useful way: it was true of the derivation **as written**, and
nothing keeps the derivation pure. The derivation is an *expression*.

Fork C, reproduced here — one rogue pair appended *inside* the `fromEntries` argument, which keeps
the index-signature type so the `as` cast stays clean:

```ts
Object.fromEntries([
  ...STATUS_TONES.map((tone) => [tone, `sk-card--status-${tone}`]),
  ['rogue', 'sk-card--status-rogue'],
])
```

Against that edit, `typecheck-all` passes for five projects, `build-element-markup` regenerates and
**writes `SkCardStatusRogueHTML`** with a class in no stylesheet, and `check-adopted-css-boundaries`,
`check-element-css-hygiene`, `check-no-css-in-source`, `check-elements-entries`,
`check-manifest-content`, `check-part-ratchet` and htmlhint all stay green.

So the assertion is restored. Against two authored lists it restated an obligation; against a
derivation it constrains **the expression**, which is the only authored thing left to get wrong.
Verified red-first with Fork C applied:

```
 × the card's status keys are sk-status-indicator's tone vocabulary, in order   113ms
 ✓ every card status modifier is the BEM family for this block                    1ms

 FAIL fixtures/elements-behaviour/src/sk-card.test.ts > the card's status keys are
      sk-status-indicator's tone vocabulary, in order
 AssertionError: expected [ 'neutral', 'info', 'success', …(4) ] to deeply equal
                          [ 'neutral', 'info', 'success', …(3) ]
    232| expect(Object.keys(CARD_STATUSES)).toEqual([...STATUS_TONES]);
       |                                    ^
 Tests  1 failed | 12 passed (13)
```

Note the second line of that output. The BEM-family test **cannot** stand in for the equality
assertion: `expect(cls).toBe(`sk-card--status-${tone}`)` derives its expectation from the key under
test, so it is self-fulfilling for any key, `rogue` included. That is exactly why deleting the
equality assertion and keeping only this one left Fork C undetected. It is kept as a separate test
because it catches something the key-level assertion cannot — a value pointing at another
component's BEM block — and its own docstring now says so.

Suite: **398 tests on `1f95a35`, 399 now.** The one net addition is the split of the old two-part
test into a key test and a value test.

`mutations.json`'s note is corrected to match: what #216 removed is one *shape* of fork — two lists
that can drift — and the arm-less boundary its #177 note named is **unchanged**, still held by an
ordinary test, because there is still no ADR-11 id for "the expression that derives one component's
map from another's vocabulary".

### The leaf property is GATED, not requested

`status-tones.ts`'s "keep this file a leaf" comment read as a guarantee over a property nothing
held. Measured by the reviewer, and reproduced here:

- `import { css } from 'lit'` added to `status-tones.ts` left `build-element-markup --check`
  **green, exit 0** — some browser-facing modules survive evaluation in Node by accident, so "it
  would blow up" is not a mechanism.
- `import '../define.js'` did fail, but with `customElements is not defined` reported against
  `sk-card.markup.ts` — not the file that gained the import — on whichever unrelated PR touched a
  markup module next.

A gate is proportionate here rather than disproportionate, for two reasons: the whole #216 fix rests
on this property, and the check is ~30 lines inside a script that is already gate-wired, so it needs
no new CI step and no new registration. `build-element-markup.mjs` now reads each markup module's
import list from esbuild's metafile **before evaluating anything** — the technique
`check-elements-entries.mjs` documents at length, because a regex over source counts commented-out
imports, legal comments and specifiers inside strings — and refuses a bare specifier, an
unresolvable one, or a target that is not itself a leaf. It fails closed if esbuild ever stops
keeping `external: ['*']` to a single metafile input, so the check cannot silently disarm.

All three attacks, after:

```
❌ packages/elements/src/status-indicator/status-tones.ts is imported by
   packages/elements/src/card/sk-card.markup.ts, and it is NOT a leaf.
   It imports: lit
exit=1

❌ packages/elements/src/status-indicator/status-tones.ts is imported by
   packages/elements/src/card/sk-card.markup.ts, and it is NOT a leaf.
   It imports: ../define.js
exit=1

❌ packages/elements/src/card/sk-card.markup.ts imports `lit` — a BARE specifier.
exit=1
```

Each names the file that holds the import. The `status-tones.ts` comment now states that the
property is enforced and records the two measurements that made a gate necessary.

## #219 — one id, and the principle written down

`expected-stories.json` before: **180** ids, prefixes exactly `elements` and `primitives`.
(An earlier reading of this file gave 160 — that is the figure its own last `$comment` note leaves
a reader with, and it is three missions stale. Counted, not read.)

Added: `components-card--statuses-greyscale`, under a `sk-card (static path)` key. Total 180 → 181.

Why that id and no other: `kitty-specs/card-status-tone-axis-01M1VJNY/implementation-evidence.md`
names `Greyscale` **and** `StatusesGreyscale` as its proof that a status tone is never the sole
carrier of meaning. #177 ratcheted the element-layer half; the static half was outside — and the
static path is the no-JavaScript consumer ADR-10 §3 exists to serve.

Verified against a real build rather than an export name:

```
components-card--statuses-greyscale: present, type "story"
declared 181 == "total" 181, missing []

```

The `$comment` now states the scope that replaces the exhausted one — the elements, plus any story
a mission has named as acceptance evidence — and the principle: **a story cited as proof is
ratcheted in the same commit that cites it.**

**Not the whole `packages/styles` catalogue.** #219 raises that as an open question and it is a
larger scope decision than a follow-up mission should take. The sweep that bounds the narrow fix:
`kitty-specs/` holds exactly **one** `implementation-evidence.md` today, and it cites exactly one
styles-layer story. There is no backlog of cited-but-unratcheted stories behind this one.

## #220 — the doc moves, the artifact does not

Measured from the generated catalogue: the generator bins by prefix only, and the real categories
are `--sk-status-` → `status` and `--sk-on-` → `on` (11 tokens: five `--sk-on-tint-*`, six
`--sk-on-status-*`).

`docs/contributing/adding-a-token.md`'s single `--sk-status-` / `--sk-on-status-` row becomes two
rows naming the real categories, plus a short section stating the convention: `on` is the union of
every `--sk-on-*` token whatever it pairs with, which is why `--sk-on-tint-mint` already sits away
from its own pair `--sk-surface-tint-mint`; pairing says which tokens you must add together, and is
not what `categories` groups by.

This is #220's **option 2**, taken deliberately. Option 1 (bin by pair) changes a published
artifact that Stylelint and the docs site consume; per the mission brief that belongs to the
operator, not to a follow-up. `packages/tokens/dist/token-catalogue.json` is untouched.

## Not done, deliberately

  operator answers it.
- **The catalogue binner is not changed.** #220's option 1/3 alter a published artifact.
- **`build-vue-types.mjs` is not changed.** The constraint is confirmed to remain; forcing it was
  explicitly out of scope.
- **The three duplicated escaping helpers are not merged.** #163 owns that, and it is now unblocked
  by this change — the comments justifying each copy said the generator made sharing impossible,
  and they have been corrected to say it no longer does. Note the new leaf gate applies to a shared
  escaper too: it would have to import nothing, which an escaper naturally does not.

  binds an arm to a declared (id, subject) pair and guard 4 requires the red test to carry an
  `[SC-NNN]` marker, and there is still no ADR-11 id for this claim. That is the fourth-time
  boundary the #177 note names, unchanged.

  filtered-suite redesign.
